## 三、过程中遇到的三个坑（已解决）

### 1. GamingServices 是「受保护服务」
`Set-Service` / `sc config` 被 SCM 拒绝，即使管理员也报「拒绝访问」。
但 `HKLM\SYSTEM\CurrentControlSet\Services\GamingServices` 的 ACL 里
Administrators 是 FullControl，因此**直接写注册表 `Start` 值**：
`2`（自动）→ `3`（手动），成功。

### 2. FeverGamesService 卡死导致脚本永久阻塞
`FeverGamesService.exe` 忽略 STOP 控制指令 → SCM 把它挂在 `StopPending` →
PowerShell 的 `Stop-Service` **无限等待**，导致提权脚本卡住。
处置：强杀该进程解除悬挂状态，之后改用**有超时上限**的停止方式。

### 3. WPS 会「自愈」重建被删的自启项 ⚠️
`WpsUpdateTask_Administrator`（**每小时**触发）在运行后会重新注册
`WpsUpdateLogonTask_Administrator`。实测：13:22 删除 → 13:25 该任务运行 → 登录任务复活。
处置：把自愈链两个任务一起删掉。
**注意：以后一旦启动 WPS Office，它可能再次重建这两个任务。**
→ 这就是需要 `REVERIFY.ps1` 的原因。

| 脚本 | 用途 |
|---|---|
| `scripts\RESTORE.ps1` | **一键还原**全部自启项（须管理员） |
| `scripts\REVERIFY.ps1` | **事后复核/自愈**：清掉任何自己回来的项（须管理员） |
| `scripts\REVERIFY.ps1 -WhatIfOnly` | 只检查、不改动 |
| `scripts\APPLY-CHANGES.ps1` | 本次实际执行的清理脚本 |
| `scripts\FIX-GAMINGSERVICES.ps1` / `FIX-STOP-SERVICES.ps1` | 上述坑 1、坑 2 的修补脚本 |

脚本会自动定位上级目录，放在哪一层都能跑。
